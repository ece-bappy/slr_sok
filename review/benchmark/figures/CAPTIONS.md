# Figure captions

Generated by `make_figures.py` from the committed CSVs, so the numbers match the plots. Copy into the paper as-is; every caption names the metric and the test malicious share.

## fig_a_collapse

**Performance collapse beyond random splits.** XGBoost, features G1+G2 without timing (the only set available for every dataset and protocol); bars are the mean over 5 seeds, whiskers ± 1 SD. Top: PR-AUC; the black tick on each bar is that test set's no-skill PR-AUC (the malicious share), because PR-AUC is not comparable across test sets with different prevalence. Bottom: macro-F1 at the validation-selected max-F1 threshold. E1 random split; E2 grouped by infection case (MTA), capture (MCFP, RAID) or client host (HIKARI); E3 trained on older years, tested on newer (infeasible for MCFP and RAID, where year and class coincide); E4 trained on the group's dataset and tested on the dataset named under it (MTA→MCFP, MCFP→MTA, RAID→MTA; HIKARI has no same-concept partner). † HIKARI E2 and E3 (outlined bars) are 2-attacker transfer tests (one attacker IP in training, the other in test), not grouped-generalisation estimates. Test malicious share: MTA: E1 49%, E2 49%, E3 38%, E4 34%; MCFP: E1 34%, E2 34%, E4 49%; RAID: E1 37%, E2 37%, E4 49%; HIKARI: E1 5%, E2 1%, E3 8%.

## fig_b_tiers

**Accuracy by TLS visibility tier.** XGBoost, 5 seeds. Tiers are simulated by masking feature groups on the same flows: full = G1–G5; TLS 1.3 = without the certificate group (G4); TLS 1.3 + ECH = flow statistics and packet sizes/directions/timing only (G1, G2). Points are mean PR-AUC; whiskers are the mean 95% bootstrap CI for the three left groups and ± 1 SD over seeds for the per-TLS-version groups (right of the dotted line; the flows of the MTA E3 test set split by the TLS version actually negotiated). The y-axis does not start at 0. Test malicious share: MTA E2 73%; MTA E3 48%; MCFP E2 92%; MTA E3 TLS 1.2 flows 44%; MTA E3 TLS 1.3 flows 56%.

## fig_c_fingerprints

**Fingerprints under drift.** Top: XGBoost on G1–G4 with no fingerprint, or with JA3/JA3S, JA4/JA4S or both added (E9). Bottom: every tabular model family, no fingerprint vs both. Training on MTA ≤2022 (left) or on MCFP (right); test is always MTA 2023–26. Points are mean PR-AUC over 5 seeds; whiskers are the mean 95% test-set bootstrap CI, which does not include seed-to-seed variation (SD up to 0.06 for XGBoost and LightGBM on MCFP → MTA; see SUMMARY_crossfamily.md). The y-axis does not start at 0. Test malicious share: MTA ≤2022 → 2023–26 48%; MCFP → MTA 2023–26 48% (the same test flows in both scenarios). About half of the test flows carry a JA3 or JA4 value never seen in MTA training (53% / 52%).

## fig_d_early

**Early detection.** XGBoost on the features visible after the first N packets of a flow (E6), mean PR-AUC over 5 seeds; solid = with timing, dashed/hollow = without. Thin horizontal lines: whole-flow features, all groups (dashed: without timing). The y-axis does not start at 0. N = 3 (shaded) covers only the TCP handshake; per-feature-set deduplication removes 87–99.8% of flows there, so those points describe an unrepresentative residue, not detection. Test malicious share for N ≥ 5 (varies with deduplication): MTA E2 24%–74%; MTA E3 21%–48%; MCFP E2 20%–92%.

## fig_e_origin_probe

**Dataset-of-origin probe.** An XGBoost classifier trained to tell which dataset a *benign* flow comes from, using G1+G2 without timing, with a split grouped by capture/host (seed 0). Cells are row-normalised (test flows per true source: RAID 15,000, HIKARI 15,000, MCFP (CTU-Normal) 15,000, MTA bg 3,923). Metric: balanced accuracy 0.989 ± 0.001 over 5 seeds, against a chance level of 0.25 (4 classes). Any benchmark that mixes benign and malicious traffic from different sources can be separated by environment alone.
